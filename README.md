# OpenCertCraft

[![CI](https://github.com/NicolasDiCostanzo/opencertcraft/actions/workflows/ci.yml/badge.svg)](https://github.com/NicolasDiCostanzo/opencertcraft/actions/workflows/ci.yml)
[![License: AGPL-3.0](https://img.shields.io/badge/License-AGPL%203.0-blue.svg)](./LICENSE)

A certification-agnostic quiz web app for exam preparation. Ships with several certification question banks built in; other certifications are added as new built-in bundles — request one via a GitHub issue.

**Live at [opencertcraft.com](https://opencertcraft.com).**

Built with **Vue 3 + TypeScript + Vite**, pinned with **Pinia**. The frontend is a **static site** — no server, no database, no build-time secrets — so you can host it on any static host or run it locally in a minute. Progress lives in your browser; an account is optional and only used to sync it.

> [!IMPORTANT]
> **Unofficial project — not affiliated with, endorsed by, or sponsored by AWS, Anthropic, or any certification body.** All certification names and trademarks are the property of their respective owners. Questions here are reconstructed from **community-shared, non-official sources** (principally [ExamTopics](https://www.examtopics.com)) rather than official vendor material, and the **explanations and theme tags were LLM-generated — so they can be wrong.** Treat it as practice material only. See [Question accuracy](#question-accuracy).

## Question accuracy

**Please read this before relying on the content.** Since these questions come from community-shared sources rather than from AWS or Anthropic, **treat everything here as practice material, not as authoritative exam content.**

**The explanations and theme tags were generated by an LLM, so they can be wrong.** This applies to:

- **Explanations** — every question's "why this is correct" rationale was written by a language model from the question text and answer key. It is not an official rationale, and it is not guaranteed to be correct, complete, or even sensible in every case.
- **Theme tags** — the topic / service / concept / question-type labels used for filtering were inferred by an LLM. Some will be debatable, and a question can be argued into a different group entirely.

The **question text and answer keys** come from the community-shared sources themselves, and were taken from the most-accepted community answer, corroborated against vote counts where available — and flagged for review when the source was ambiguous. That part is *not* LLM-generated, but it is still only as good as those sources.

Because the generated parts can be wrong, **if you spot a bad explanation, a mis-tagged question, a wrong answer key, or a question that no longer matches the official exam, please [open an issue](https://github.com/NicolasDiCostanzo/opencertcraft/issues).** That's the single most useful contribution you can make, and corrections are merged the same way as any other change. Quote the question id, and say what it should say instead.

## Features

- **Two quiz modes** — **Preparation** (immediate feedback, filters, and an optional timer of your chosen length, ideal for drilling weak areas) and **Exam** (fixed to the real exam's question count, duration and topic weighting, deferred feedback).
- **Replay modes** — practice only what you got wrong, only flagged questions, only unattempted ones, or sample proportionally to the real exam's published domain weights. Questions are always shuffled.
- **Theme filters** — include/exclude by topic, service, concept, or question type, with AND/OR composition per group.
- **Per-question progress** — the app tracks how you've done on *each individual question*, so "drill the exact topics I keep failing" is a first-class action rather than something you assemble by hand.
- **Local-first, private by default** — per-question stats, flags, and full quiz history are stored in your browser. **No account required, and no analytics or tracking of any kind.**
- **Optional account for sync** — sign in to carry your progress across devices via an optional AWS backend (Cognito + API Gateway + Lambda + DynamoDB). Nothing is uploaded unless you sign in.
- **Mobile-friendly** — study on a phone.


## Getting started

Requires **Node 22+**.

```bash
npm install
npm run dev
```

The app opens on a welcome screen, then the certification selector. From there you can start a quiz, browse your dashboard and history, configure filters, or request a certification that isn't listed.

### Commands

```bash
npm run dev         # dev server
npm run build       # type-check + build to dist/
npm run preview     # serve the production build locally
npm run test        # unit tests (Vitest)
npm run test:certs  # cert-bundle gate: manifest + theme integrity
npm run test:e2e    # end-to-end tests (Playwright, Chromium)
npm run lint        # ESLint
npm run typecheck   # vue-tsc
npm run knip        # unused code/dependency check
```

### Self-hosting

The frontend is fully static — `npm run build` emits a `dist/` directory you can serve from any static host, with no server-side runtime. Routes use clean paths (`/`, `/cert`, `/certs/<CODE>/quiz`), so **the host must rewrite unknown paths to `index.html`** or deep links will 404. The project's own S3 + CloudFront setup already does this via `CustomErrorResponses`; on another host add the equivalent rule (Netlify `_redirects`, a `404.html` on GitHub Pages, an nginx `try_files $uri /index.html`).

To deploy to the project's own S3 + CloudFront setup:

```bash
npm run deploy:front   # build + S3 sync + CloudFront invalidation
```

Defaults to stack `sam-app` (the stack `samconfig.toml` deploys to); override with `STACK_NAME=<stack>`. `template.yaml` (SAM) defines the optional AWS backend — Cognito user pool, HTTP API, two Lambdas, DynamoDB, and the S3 + CloudFront layer with Origin Access Control and ACM.

## Adding a new certification

There is no in-app upload. Adding a cert is a **data change, not a code change** — a question bundle plus one manifest entry, because all exam-specific content lives in JSON and the app adapts to whatever taxonomy a cert declares.

1. **Open an issue** requesting the certification.
2. If you already have the questions formatted, attach the JSON per [`schema-reference.md`](./docs/certifications/schema-reference.md).
3. Otherwise, hand [`adding-a-certification.md`](./docs/certifications/adding-a-certification.md) to any LLM together with your raw questions (e.g. an ExamTopics `.txt` dump) and it returns the formatted bundle and manifest entry. Attach the result to the issue, or open a PR adding `src/assets/<CODE> questions.json` plus an entry in `src/assets/cert-manifest.json`.
4. A maintainer reviews and merges. Certs are discovered at build time, so it goes live on the next deploy.

Then run `npm run test:certs` — the authoritative validity check. It fails on a malformed bundle, a missing or mismatched manifest entry, a question count that disagrees with the file, and theme problems (a tag a question uses but the registry doesn't declare, a declared value no question uses, an untagged question, sibling certs whose theme groups are named differently). Schema validation alone won't catch a bad theme, because an undeclared tag is only a *warning* there — and it surfaces to the user as an empty filter result.


## Testing

Unit tests cover behavior, not trivia: scoring and pass thresholds, filter composition, session state transitions, answer correctness, sampling, and bundle validation. End-to-end specs drive a real browser through the quiz flow with auth faked, so they need no AWS account.

CI runs lint, typecheck, unit tests, build, end-to-end tests, an unused-code check, and `npm audit` on every PR.

```bash
npm run test && npm run test:e2e
```
